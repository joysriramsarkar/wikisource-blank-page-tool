# ফাঁকা পাতা — Next.js সংস্করণ

উইকিসংকলনের বইয়ের ফাঁকা/খালি পাতা খুঁজে দেখার, স্ক্যান যাচাই করার এবং
**“লেখাবিহীন”** (pagequality level 0) হিসেবে প্রুফ করার Next.js + TypeScript
সংস্করণ।

Flask সংস্করণটি রিপোর রুটে আছে; এটি তার নতুন, per-user session ভিত্তিক
সংস্করণ।

---

## দুটো এডিট মোড

### ১. ম্যানুয়াল / পাবলিক (কোনো বট পাসওয়ার্ড লাগে না)

- বিশ্লেষণ, স্ক্যান ব্রাউজার, ভিউয়ার — সবই কাজ করে।
- প্রতি পাতার জন্য **“উইকিসংকলনে খুলুন”** বাটন; পাতাটি খুলে উইকিসংকলনের
  Page: পাতায় **“লেখাবিহীন”** বাটনে ক্লিক করে সেভ করতে হয়।
- “লেখাবিহীন কপি” চাপলে প্রয়োজনীয় উইকিটেক্সট ক্লিপবোর্ডে যায়।
- একসাথে বাল্ক সেভ হবে না — এক পাতা করে। এটাই সাধারণ অ্যাকাউন্টের নিরাপদ পথ;
  স্বয়ংক্রিয়/বাল্ক সম্পাদনায় বট নীতির সমস্যা এড়ানো যায়।

### ২. বট মোড (প্রত্যেকের নিজের বট পাসওয়ার্ড)

- ব্যবহারকারী নিজের `ব্যবহারকারী@বটনাম` ও বট পাসওয়ার্ড দিয়ে লগইন করে।
- সার্ভার শুধু **MediaWiki session cookie** সংরক্ষণ করে — **বট পাসওয়ার্ড
  সংরক্ষণ করে না**।
- সেশনটি প্রতি ব্রাউজারের জন্য আলাদা, `httpOnly` + `Secure` + এনক্রিপ্টেড
  (JWE) কুকিতে থাকে; মেয়াদ ৮ ঘণ্টা।
- লগইন থাকলে একসাথে সব নির্বাচিত পাতা সেভ করা যায়; ডিফল্ট **পরীক্ষা মোড**
  (dry-run) চালু।
- প্রত্যেকের নিজের অ্যাকাউন্ট/বট থেকে সম্পাদনা হয়; কোনো শেয়ার্ড বট সেশন নেই।

> **বট নীতি:** বাল্ক সম্পাদনার জন্য উইকিতে অনুমোদিত বট অ্যাকাউন্ট ব্যবহার
> করুন। সাধারণ অ্যাকাউন্ট দিয়ে স্বয়ংক্রিয়/বাল্ক সম্পাদনা করলে উইকির বট
> নীতিতে ব্লক হতে পারে। সাধারণ ব্যবহারকারীর জন্য ম্যানুয়াল মোড।

**OAuth/NextAuth নয় কেন?** OAuth দিয়ে সাধারণ অ্যাকাউন্টের বাল্ক সম্পাদনা
বট-পলিসি ঝুঁকি তৈরি করে; আর NextAuth শুধু আপনার অ্যাপে লগইন করায়, উইকিতে
এডিটের অনুমতি দেয় না। তাই এখানে **প্রতি-ব্যবহারকারীর বট পাসওয়ার্ড সেশন** +
**ম্যানুয়াল পাবলিক মোড** — আপনার চাওয়া অনুযায়ী।

## যা যা আছে

- নির্ঘণ্ট `<pagelist>` পড়ে ফাঁকা পাতা খোঁজা; বিদ্যমান খালি `পাতা:` পৃষ্ঠাও।
- শুধু ফাঁকা/খালি পাতার গ্যালারি, স্ক্যান থাম্বনেইল, বড় ভিউয়ার, জুম।
- পুরো বইয়ের **স্ক্যান ব্রাউজার** (৪৮ পাতা/পৃষ্ঠা, jump), স্ক্যান দেখে
  তালিকায় হাতে পাতা যোগ।
- **লাইভ সার্চ** — সার্চ বক্সে লিখলেই উইকিসংকলনের নির্ঘণ্ট থেকে ফলাফল।
- লেখা আছে এমন পাতা কখনো জোর করে খালি করে না; সেভের আগে প্রতিটি পাতা
  আবার লাইভ যাচাই করে।
- ডিফল্ট dry-run; edit conflict/redirect/মুছে ফেলা পাতা নিরাপদে সামলায়।
- **Stateless API**: কোনো global analysis cache/login state নেই; Vercel-এর
  cold start-এও সেশন কুকি থেকে কাজ করে।

## চালু করা

```bash
cd next-app
npm install
```

`.env.local` তৈরি করুন (বা `.env.example` কপি করুন):

```env
SESSION_SECRET=একটি-দীর্ঘ-র‍্যান্ডম-স্ট্রিং
```

`SESSION_SECRET` ছাড়া production-এ লগইন কাজ করবে না (dev-এ একটি fallback
আছে, কিন্তু সেটি নিরাপদ নয়)।

```bash
npm run dev
```

খুলুন <http://localhost:3000>। Next dev-এ `127.0.0.1` থেকেও খুলতে চাইলে
`next.config.ts`-এ `allowedDevOrigins: ["127.0.0.1"]` দেওয়া আছে।

Production:

```bash
npm run build
npm start
```

## Vercel-এ ডিপ্লয়

1. GitHub রিপো থেকে নতুন Vercel প্রজেক্ট তৈরি করুন।
2. **Root Directory** দিন `next-app` (রিপোর রুট নয়)।
3. Environment Variables-এ **`SESSION_SECRET`** দিন (৩২+ র‍্যান্ডম অক্ষর)।
4. Deploy।

- আগের Flask অ্যাপের Vercel প্রজেক্ট আলাদা; এটি নতুন প্রজেক্ট।
- বিশ্লেষণ route-এ `maxDuration = 60` দেওয়া; Vercel প্ল্যানের ফাংশন সময়সীমা
  অনুযায়ী খুব বড় বইয়ে analyze সময় নিতে পারে। বড় বইয়ের জন্য persistent
  host (Render/Railway) বেশি নিরাপদ।
- সেশন কুকিতে MediaWiki session cookies থাকে; তাই HTTPS বাধ্যতামূলক
  (Vercel-এ স্বয়ংক্রিয়)।

## নিরাপত্তা

- বট পাসওয়ার্ড শুধু লগইনের অনুরোধে ব্যবহৃত হয়; সার্ভার/ডেটাবেসে সংরক্ষণ
  হয় না।
- শুধু MediaWiki session cookies এনক্রিপ্টেড JWE কুকিতে রাখা হয়
  (`SESSION_SECRET` দিয়ে)। কুকি `httpOnly`, `Secure`, `SameSite=Lax`।
- লগআউটে Wiki session বাতিল করার চেষ্টা + কুকি মুছে ফেলা হয়।
- সেভের আগে সার্ভার পাতা লাইভ পড়ে: লেখা থাকলে বাদ, redirect বাদ,
  `assert=user`, `baserevid`/`nocreate`/`createonly`।
- পাবলিক টুলে নিজের বট পাসওয়ার্ড শুধু বিশ্বস্ত HTTPS ডিপ্লয়ে দিন এবং
  সন্দেহ হলে Special:BotPasswords থেকে বাতিল করুন।

## সীমাবদ্ধতা

- বিশ্লেষণ সব বিদ্যমান `পাতা:` পৃষ্ঠার content পড়ে; খুব বড় বইয়ে সময় লাগতে
  পারে।
- Vercel serverless-এ function duration সীমা আছে; বড় বইয়ে timeout হতে পারে।
- সেশন কুকির আকার MediaWiki cookies-এর উপর নির্ভরশীল; খুব বড় হলে আলাদা
  session store দরকার হবে (এখনো যোগ করা হয়নি)।
- পাবলিক মোডে স্বয়ংক্রিয় সেভ নেই — ইচ্ছাকৃতভাবে, নিরাপত্তার জন্য।
- পুনর্নির্দেশ/ডুপ্লিকেট পাতা মুছে ফেলে না; শুধু দেখায়।
